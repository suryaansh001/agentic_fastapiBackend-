Phase 2 — Canonical Tool Registry
New app/agent/tools/registry.py: ToolDefinition = name, description, input_schema (derived from the existing pydantic Input models in tools.py), risk_tier (safe/dangerous/approval_required), permission, timeout_ms, idempotency policy, executor, audit metadata. ToolRegistry provides get (unknown → reject), list_for(agent_type, user) (permission-filtered), validate. Consumers: LangGraph engine, application execution layer, authorization, validation, auditing — all the same registry. Delete the three ToolSchema lists in orchestrator.py and the per-agent HTTP tool routers. Flow: LLM tool call → registry lookup → permission check → risk check → arg validation → approval if required → execution → audit/event.

Phase 4 — AgentExecutionEngine + LangGraph (replaces the loop)
- app/agent/engine/__init__.py — AgentExecutionEngine ABC: start(run, request), resume(run, decision), cancel(run), get_status(run).
- app/agent/engine/langgraph_engine.py — LangGraphEngine (only production implementation). StateGraph per agent type; nodes: classify (intent routing, replaces keyword route()), call_llm (adapter), guard (permission+risk via registry), execute_tool (registry-bound, handles any tool call), finalize. Conditional edges: tool_calls → guard → execute_tool → call_llm; else → finalize. Graph-level retries on transient LLM errors.
- AgentGraphState (TypedDict scratchpad): messages, tool results, iteration, budget remaining, produced files, interrupt payload. No CRM data — PG remains source of truth.
- Checkpointer: langgraph-checkpoint-postgres (AsyncPostgresSaver) on schema agent_checkpoint (separate from public); AgentRun.graph_thread_id links run ↔ checkpoint thread. Define retention/cleanup job and serialization limits.
- Delete: Orchestrator.run/resume, _extract_tool_calls, _safe_json (defined 3×), the forced SELECT * FROM deal LIMIT 10 fallback (invalid model output → safe error through graph policy, never fallback SQL).
- unified_router.py becomes a thin client: create AgentRun → engine.start → respond.
Dependencies to add: langgraph, langgraph-checkpoint-postgres, asyncpg, opentelemetry-* (Phase 6).
Phase 5 — Durable HITL
New AgentApproval model (alembic revision): run_id, interrupt_id, tool_name, arguments_hash, requester_id, approver_id, decision, created_at, resolved_at. Dangerous tool node raises LangGraph interrupt() with a sanitized payload → checkpointer persists → AgentRun = WAITING_FOR_APPROVAL. New POST /api/agents/runs/{run_id}/approvals/{approval_id}: authorization (creator/owner/admin), state guard (only WAITING_FOR_APPROVAL), idempotency via existing agentRunIdempotency table keyed (run_id, interrupt_id) → engine.resume(run, decision) → Command(resume=…). Delete the old /api/agents/unified/tasks/{task_id}/approve (no authz, no idempotency). Never expose raw LangGraph resume to clients.
Phase 6 — OpenTelemetry
app/telemetry/otel.py: tracer + meter provider, FastAPI/SQLAlchemy/httpx instrumentation, manual spans for engine/graph-node/LLM/tool/HITL/child. Span hierarchy: Request → AgentTask → AgentRun → Engine → graph node → LLM → Tool → DB → HITL pause/resume → child run. Required attributes: engine.name, run.id, task.id, tool.name, agent.type. Metrics: queue latency, LLM/tool latency, tokens, cost, retries, failures, approval/rejection rate, task completion, tool selection, child depth/cost. OTLP export endpoint configurable; console exporter in dev. LangSmith explicitly not the system of record.
Phase 7 — Subagents (no DeepAgents)
AgentRun columns (alembic revision): parent_run_id, execution_engine, delegation_depth, token_budget, max_children, timeout_ms, structured result. Engine spawns children as LangGraph subgraphs/Send with enforced caps: max depth (default 2), per-child token budget (metered by the LLM adapter), max children, timeout, cancellation propagation (engine.cancel cascades), failure-propagation policy. DeepAgents is not added; if adopted later it implements the same AgentExecutionEngine contract, leaving FastAPI/AgentTask/AgentRun/frontend/app-schema/tool-registry/telemetry untouched.
Testing plan (what each proves)
Routing accuracy; tool selection; native tool calls execute without text scraping; malformed LLM output → safe error (no fallback SQL); unknown tool → reject; unauthorized tool → reject (pre-execution); approval-required tool → pause + WAITING_FOR_APPROVAL; HITL pause survives restart; duplicate approve → single execution (idempotency); unauthorized approver → 403; checkpoint recovery mid-tool-call; token/iteration budget exhaustion = normal ending; worker claim/lease/recovery, no double-claim; auth → 401/403; path traversal, SSRF, SQL-injection rejection; final CRM writes land via service layer with audit events; child depth/budget caps.

2. SQLite→PG data migration needs a tested script (alembic history is empty).
3. Checkpoint schema growth — retention job required.
4. Deleting HTTP tool endpoints changes API surface — confirm frontend doesn't call them (tests currently do; they get replaced).
5. Sync chat + worker both create runs — the run-creation path must be shared to avoid divergence.
